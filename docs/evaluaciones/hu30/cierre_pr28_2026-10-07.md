## Salvedad de la aprobación

Los JSON históricos conservan CRLF intencional y no deben normalizarse:
su contenido binario, manifiestos y resultados permanecen intactos.
La política `whitespace` específica para esos JSON reconoce CR al final de
línea y mantiene la detección de espacios sobrantes, líneas finales vacías y
espacios antes de tabulaciones. No se desactiva el control global de formato.
Una regresión Git local verifica ambos comportamientos y los bytes conservados.

Para checkouts antiguos, agregar `.gitattributes` no garantiza rematerializar
archivos que Git considera sin cambios. Por eso la validación de backend se
ejecutó en un checkout Windows independiente creado con `core.autocrlf=true`,
sin `.env` y utilizando las dependencias ya instaladas. No se recomienda
normalizar ni recalcular hashes para ocultar un problema del checkout.
